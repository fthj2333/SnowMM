# 部署恢复与未配置目录时的资源库操作修复

## 问题与行为

1. 中断事务可能已将旧部署移入事务备份，但旧清单尚未提交。此前管理器先读取文件是否存在并生成启用方案，再在部署内部恢复事务，导致方案遗漏原先启用项。现在通过统一入口先恢复、再读取状态，覆盖刷新、启停、方案、版本、目录移动和回收操作。恢复失败则停止新请求；游戏运行时若存在需恢复的事务，要求退出后重试，不改写待办。
2. 资源库改名、分类移动和回收此前无条件执行部署事务，未设置应用目录时因此失败。现在这些操作在无部署配置时只修改资源库，保留目录校验、原件、回收目录和失败回滚；实际部署仍要求配置有效应用目录。未配置部署的版本选择也只更新库内记录。

## 验证

- 新增16项管理器级回归，使用真实一次性文件、清单、备份和事务日志；初始11项测试在修复前有9项失败，修复后通过。
- 覆盖中断后的启停、刷新、方案、已启用模组改名、版本切换、删除无关项、恢复错误、游戏运行限制、待办保留，以及未配置目录时的资源库操作和移动失败回滚。
- 完整回归151项：150通过，1项因测试进程缺少真实Windows链接权限跳过。Ruff与修改文件的git diff --check通过；Qt离屏工作流通过。
- 没有运行游戏、操作真实部署或存档，本说明描述源码修复；本地EXE已另行重建为1.1.0-enhanced.4，公开源码更新和发布状态见Fork分支。
